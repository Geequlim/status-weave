# Status Weave 产品形态

本文记录 Status Weave 已确认的产品形态与交互原则，作为后续界面设计、配置模型和验收工作的依据。

## 产品目标

Status Weave 以 GNOME Vitals 为主要体验标杆：指标覆盖需要足够丰富，面板显示需要紧凑、美观且易读；在此基础上，充分利用 Cinnamon applet 的右键菜单、多实例和原生设置能力，提供比 Vitals 更直接的布局编排体验。

产品定位可以概括为：

> 像 Vitals 一样丰富漂亮，但像原生 Cinnamon applet 一样可以就地配置、自由编排和多实例组合。

参考：

- [GNOME Vitals](https://github.com/corecoding/Vitals)
- [Vitals on GNOME Shell Extensions](https://extensions.gnome.org/extension/1460/vitals/)

## 三层交互

### 左键：查看实时状态

左键打开实时详情面板，按 CPU、内存、GPU、温度、风扇、网络、存储等类别展示当前数据。

这一层以快速阅读为目标，不混入指标排序和布局编辑，避免查看与配置互相干扰。

详情面板只包含当前 applet 实例中实际显示的指标，并按实例布局顺序生成详情分页。只有一个详情指标时直接展示内容；存在多个详情指标时，分页切换始终贴近触发它的面板：顶部面板将分页放在详情顶部，底部面板将分页放在详情底部，使切换位置不受各详情页高度影响。隐藏槽位和分隔符不生成详情页；同一数据来源的重复展示槽位共享一个详情页。

### 右键：编排当前实例

右键菜单负责当前面板实例的高频配置：

- 显示或隐藏指标。
- 将指标向左或向右移动。
- 添加、删除或移动分隔符和分组。
- 切换紧凑、标准或详细显示格式。
- 应用“概览”“GPU / 风扇”“网络”等布局预设。
- 重置当前实例布局。

第一版采用明确的“向左移动 / 向右移动”菜单操作，不要求立即实现拖拽。后续可以在不改变配置模型的前提下升级为拖拽式布局编辑器。

### 完整设置：高级配置

Cinnamon 原生配置界面负责低频和高级选项：

- 告警阈值与状态颜色。
- 刷新频率。
- 单位、精度和格式。
- 设备与传感器映射。
- Provider 行为、诊断和真正的全局设置。

## 有序布局模型

每个面板实例保存一份独立的有序槽位列表，而不是只保存一个“已启用指标集合”。例如：

```text
CPU 使用率 → CPU 温度 → 内存 → 分隔符 → 下载 → 上传
```

每个槽位至少具有稳定 ID、类型和显示状态。显示或隐藏指标不应破坏它原来的位置；重新启用后应回到之前的顺序。排序只修改当前实例的槽位顺序，不重新创建 Provider，也不触发重复硬件采样。

分隔符和分组也属于布局槽位，因此可以与指标一起排序，而不是由展示代码硬编码。

### 展示项模型

槽位不是固定的“CPU 块”或“内存块”，而是一个可重复添加的展示项。每个指标槽位分别保存：

- `slotId`：当前实例中的稳定位置身份，允许同一指标出现多次。
- `metricId`：数据语义，例如 `cpu.usage` 或 `memory.usage`。
- `format`：当前槽位采用的显示预设。
- `visible`：是否显示；隐藏不删除槽位和原始位置。

采样数据、聚合语义和显示格式必须分离。同一份内存快照可以同时派生百分比、已用量、已用/总量和可用量；这些展示项不应重复读取 `/proc/meminfo`。

首批 CPU 与内存显示预设为：

- CPU：`18%`、`CPU 18%`、`CPU 18.4%`。
- 内存：`24%`、`RAM 24%`、`RAM 7.4 GB`、`RAM 7.4 / 31.1 GB`、`RAM 可用 23.7 GB`。

右键菜单分为“添加展示项”和“当前布局”。用户可以添加 CPU、内存或分隔符；每个现有槽位可以切换显示格式、隐藏、左右移动、复制或移除。复制后两个槽位拥有独立 `slotId`，因此可以为同一指标选择不同格式。

后续网络、温度和 GPU 沿用同一模型；设备来源、瞬时聚合和时间窗口属于指标配置，不通过新增 Provider 查询来实现显示差异。

## 详情指标与页面架构

详情能力不能以固定的 CPU、内存字段集合实现。每个可展示指标需要通过统一定义描述：

- 稳定的指标 ID 和可选的数据来源 ID。
- 面板摘要值、可用状态、单位和更新时间。
- 指标专属的详细快照类型。
- 历史记录策略。
- 详情页标题、图标和页面工厂。

详情弹窗外壳只负责从当前实例布局派生分页、切换页面、处理溢出和管理页面生命周期，不包含任何 CPU、内存或设备专属展示逻辑。

每个指标拥有独立的详情页面模块。简单页面可以使用单个文件；复杂页面应升级为独立目录，容纳页面、视图模型和指标专属组件。例如：

```text
src/details/
├─ detail-popup.ts
├─ detail-page-registry.ts
├─ ui/
│  ├─ detail-row.ts
│  └─ history-chart.ts
└─ pages/
   ├─ cpu-usage/
   │  ├─ page.ts
   │  └─ model.ts
   └─ memory-usage/
      ├─ page.ts
      └─ model.ts
```

详情页面只能消费共享数据层提供的当前值和历史数据，不能自行读取 `/proc`、sysfs 或执行设备命令。CPU 每核心占用率与当前频率、内存缓存、网络接口、温度传感器等复杂结构由各自的强类型详细快照表达，不压缩进通用字符串映射。

CPU 型号和内存制造商、类型、配置频率等静态硬件元数据由共享数据层按需读取一次并缓存。正常状态下，详情标题右侧优先显示 CPU 型号或内存制造商；等待和不可用状态则显示状态标签。内存类型与配置频率在内存详情底部的硬件信息分区展示。

## 历史数据缓冲

Telemetry Service 为指标保存进程内共享的有界历史缓冲，供详情页和后续图表复用。历史记录必须：

- 同时支持按最长保留时间和最大样本数限制容量。
- 为每个样本保存时间戳、可用状态和强类型值。
- 保留采样失败与恢复产生的时间缺口，图表不得错误连接不可用区间。
- 由所有 applet 实例共享，不能随实例数量重复记录。
- 采集项由所有实例当前可见指标的并集决定；没有任何实例展示的指标停止采集，也不继续增长历史缓冲。
- 与采样频率解耦，后续调整刷新间隔时仍按真实时间范围查询。
- 支持按时间范围读取，并为有限像素宽度的图表进行降采样。

CPU 每核心数据来自同一次 `/proc/stat` 读取，内存明细来自同一次 `/proc/meminfo` 读取；增加详情和历史记录不能增加相同来源的采样次数。昂贵的设备详情后续可以在详情弹窗打开时按需激活，但历史所有权仍属于共享数据层。

历史缓冲只存在于 Cinnamon 进程内，Cinnamon 重启后清空。Status Weave 不把历史指标持久化到磁盘；页面模块也不得自行创建缓存文件或数据库。

## 多实例

多实例是 Status Weave 相比 Vitals 的核心优势之一：

- 顶部实例可以显示 CPU、内存和网络概览。
- 底部实例可以显示 GPU、温度和风扇。
- 每个实例拥有独立的指标顺序、格式、阈值和预设。
- 全部实例共享 Telemetry Service 的设备发现、采样和缓存。

实例配置属于展示层；采样状态属于共享服务，两者不能耦合。

## 视觉原则

- 面板信息保持紧凑，避免大型图表和不必要的装饰。
- 图标、数值和单位使用一致的间距与层级。
- 数值刷新时尽量保持宽度稳定，减少面板抖动。
- 正常状态服从 Cinnamon 主题；警告和危险状态才使用强调色。
- 工具提示提供完整名称、设备来源、单位、状态和不可用原因；不展示采样时间。
- 左键详情面板可以比面板文本更丰富，但仍以快速阅读为目标。

## 第一版交互验收

- 用户不需要先隐藏再重新添加指标就能调整顺序。
- 右键菜单可以完成当前实例的显示、隐藏和左右移动。
- 左键详情面板只负责查看，不承担排序操作。
- 两个实例可以显示不同指标和顺序，同时复用同一份采样结果。
- 隐藏后重新启用的指标能恢复到原有位置。
- 修改布局后立即生效，不重新初始化无关 Provider。
